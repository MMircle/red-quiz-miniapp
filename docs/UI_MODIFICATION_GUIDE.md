# UI 界面修改指南

本文档面向后续维护者，用于说明红色主题随手刷题微信小程序的 UI 修改边界、页面结构和检查清单。

## 1. 页面结构

当前小程序包含 3 个核心页面：

- `pages/index/index`：首页，负责模式选择、题库状态展示、题目格式提示。
- `pages/quiz/quiz`：答题页，负责题目展示、选项选择、上一题/下一题、提交本题、即时反馈。
- `pages/result/result`：结果页，负责总成绩、称号、薄弱点建议、错题回看。

全局样式在 `app.wxss` 中定义，页面局部样式分别写在各页面 `.wxss` 文件中。

## 2. 视觉主题

整体视觉应保持红色主题，但不要把界面做成单一红色块。

推荐色彩角色：

- 主色：深红 `#b5121b`、暗红 `#8d1118`
- 强调色：金色 `#d59b2b`、浅金 `#ffe2a6`
- 背景色：米白 `#fff8ed`、浅暖色 `#fff6e8`
- 正确反馈：绿色系 `#1e6b42`、`#edf8ef`
- 错误反馈：红色系 `#8d1118`、`#fff0ed`
- 正文色：深墨红 `#301315`

修改 UI 时优先沿用这些颜色，避免新增大量相近但不统一的红色、橙色或棕色。

## 3. 组件样式原则

- 卡片圆角保持 `8px`，与当前设计一致。
- 主按钮使用 `.primary-button`，次级按钮使用 `.ghost-button`，按钮文字必须通过 flex 居中，避免只依赖 `line-height`。
- 题目、选项、解析等学习内容优先保证可读性，不要为了装饰牺牲行距和对比度。
- 长题干、长选项必须允许自动换行，不能固定单行省略。
- 移动端按钮文字不能溢出，必要时调整按钮宽度或减少文案长度。
- 页面背景保持干净，不建议加入复杂纹理、大面积图片或装饰性浮层。

## 4. 首页修改指南

相关文件：

- `pages/index/index.wxml`
- `pages/index/index.wxss`
- `pages/index/index.js`

首页主要承载“选择练习模式”的任务，修改时注意：

- `十题快练` 和 `五十题精练` 两个入口必须明显。
- 模式说明要准确反映答题规则：
  - 十题快练：10 道单选、即时反馈、结束后成绩分析。
- 五十题精练：40 道单选 + 10 道多选、答题期间只显示上一题/下一题、最后一题统一交卷后分析。
- 题库状态区域不要删除，它能帮助维护者快速发现题库格式错误。
- 如果新增模式，需要同步修改 `utils/quiz.js` 中的 `MODE_CONFIG`。

## 5. 答题页修改指南

相关文件：

- `pages/quiz/quiz.wxml`
- `pages/quiz/quiz.wxss`
- `pages/quiz/quiz.js`

答题页是最容易出现状态 bug 的页面，改 UI 时必须保留以下交互：

- 第一题时 `上一题` 禁用。
- 返回上一题后，已选答案必须保留。
- 十题快练中已提交题目必须锁定，不能重新改答案或重复改分。
- 五十题精练不设置“提交本题”，交卷前所有题目均可返回修改。
- 单选题：点击选项只表示选中；十题快练点击 `提交本题` 后锁定，五十题精练最终交卷后统一锁定。
- 多选题：点击选项可选中/取消；十题快练必须点击 `提交本题` 才锁定，五十题精练在最终交卷时统一锁定。
- 十题快练未选择答案时，`提交本题` 不可用或必须提示用户选择答案。
- 十题快练提交后立即展示正确答案、用户答案、解析和知识点。
- 五十题精练答题过程中不提前显示对错和解析。
- 快速选题号面板必须保留题号跳转、已作答状态、当前题状态和已标记状态。
- 标记功能必须支持标记/取消标记，且题号面板和题干标签应同步体现。

选项状态 class 说明：

- `selected`：当前选中的选项。
- `correct`：即时反馈时的正确选项。
- `wrong`：即时反馈时用户误选的选项。
- `locked`：题目已提交，选项不可修改。

如果调整选项 UI，必须同时检查这些状态在视觉上是否清晰可区分。

题号面板状态 class 说明：

- `current`：当前题。
- `answered`：已经选择过答案。
- `submitted`：十题快练中已经提交的题。
- `marked`：用户标记的题。

## 6. 结果页修改指南

相关文件：

- `pages/result/result.wxml`
- `pages/result/result.wxss`
- `pages/result/result.js`

结果页必须保留以下信息：

- 总分/正确率。
- 学习称号。
- 答对题数、答错题数、总题数。
- 薄弱分类建议。
- 错题回看。
- 每道错题的题干、用户答案、正确答案、知识点和解析。

称号规则由 `utils/quiz.js` 的 `getHonor` 控制。若改称号文案，需要同步确认结果页文案是否仍然自然。

## 7. 题库格式与 UI 的关系

UI 展示依赖以下字段：

- `stem`：题干。
- `options`：选项列表。
- `answer`：正确答案。
- `explanation`：解析。
- `knowledgePoint`：知识点。
- `category`：分类，用于展示分类标签和结果页薄弱点统计。
- `tags`：标签，用于后续扩展。

如果新增题库字段，例如 `sourceTitle`、`sourceUrl`、`difficultyLabel`，建议先在结果页或错题页小范围展示，不要一次性塞进答题主界面，以免干扰刷题节奏。

## 8. 修改后检查清单

每次修改 UI 后，至少检查以下场景：

- 首页两个模式入口是否都能点击进入。
- 十题快练是否只出现单选题。
- 五十题精练是否包含 40 道单选和 10 道多选。
- 第一题 `上一题` 是否禁用。
- 返回上一题后，已选答案是否保留。
- 十题快练已提交题目返回后是否锁定。
- 五十题精练返回任意题后是否仍可修改。
- 多选题是否能选中、取消；十题快练提交后是否锁定。
- 十题快练是否逐题显示即时反馈。
- 五十题精练是否没有“提交本题”，只在最后一题显示“提交试卷”。
- 题号面板是否能快速跳题，并正确显示当前题、已作答、已标记状态。
- 标记本题/取消标记是否能同步更新按钮、题干标签和题号角标。
- 结果页是否显示成绩、称号、错题和薄弱点建议。
- 长题干、长选项、长解析在手机尺寸下是否换行正常。

## 9. 建议的后续 UI 迭代

- 增加答题卡：展示每题已提交/未提交状态，方便五十题模式快速定位。
- 增加错题本入口：在结果页保存错题，后续可做专项复习。
- 增加主题专项练习：首页按党的基础知识、建党精神、“四史”、中大红色校史进入。
- 增加题目来源展示：尤其是红色校史题，方便正式上线前核验。
- 增加浅色/护眼模式：仍保留红色品牌识别，但降低长时间刷题的视觉疲劳。
